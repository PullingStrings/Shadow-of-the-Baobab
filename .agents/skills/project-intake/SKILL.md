# project-intake

1. Inspect existing files, constraints and stated goals. Distinguish prototype from production change.
2. Write a short outcome, user journey, acceptance criteria and non-goals to `docs/PROJECT.md` (using template).
3. Propose at most two viable approaches if a choice genuinely matters; otherwise choose one and record why. Do not default to a particular framework.
4. Invoke capability resolver only for missing meaningful capability.
5. Execute a minimal vertical slice and verification in the same session where practical. Ask only for essential blockers.
